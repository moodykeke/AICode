# r26：内存占用优化（先量后改）

2026-09-23。用 CDP 取基线（1440×900，切场景 / 开角色库 / 开风格预设 / 反复开卡），
问题不在"用得多"，而在**关掉也不还**。

## 基线（改前）

| 时机 | DOM 画布 | 画布占用 | DOM 节点 | JS 堆 |
| --- | --- | --- | --- | --- |
| 打开后 | 3 个 | 4.9MB | 688 | 5.5MB |
| 开一次角色库 | 81 个 | 8.0MB | 2144 | 4.9MB |
| **关掉角色库** | 81 个 | **8.0MB（不还）** | 2132 | 6.1MB |
| 切场景 + 开风格预设 | 90 个 | 9.8MB | 2949 | 13.3MB |
| 反复开卡 8 次 | 90 个 | 11.0MB | 2874 | 9.1MB |

## 六项改动

1. **角色库缩略图：懒渲染 + 关闭即释放**。78 张缩略图（110×110，约 3.8MB）原来一次性全画、关掉仍驻留；
   现在用 IntersectionObserver（提前 240px 预取）只画滚动到可见的，关闭时把画布尺寸归零。
2. **风格预设预览：关闭即释放**（8 张 300×210，约 2MB；重开时会重建）。
3. **角色卡画布：关卡即释放**（380×532×2，约 1.6MB；开卡时 `sizeCard()` 会重设尺寸）。
4. **舞台画布按面积自适应上限**：原来 retina 上 DPR 取满 2，1440 宽即约 18MB 后备存储；
   现加"舞台总像素 ≤260 万"的上限（小屏仍保持 2 倍清晰度）。
5. **基因缓存上限 4000 → 1200**（纯缓存，过大只是在占内存）。
6. **眼睛偏移不再每帧分配**：原来每帧每头 `Object.assign` 一个新对象（42 次/帧），改为每头一个复用对象。

## 改后（同样路径实测）

| 时机 | 画布占用 | 变化 |
| --- | --- | --- |
| 开一次角色库 | 5.0MB | −37%（首批只画 13/78 张） |
| 关掉角色库 | 4.4MB | **−45%**（26 张已渲染的全部释放） |
| 切场景 + 开风格预设 | 6.2MB | −37% |
| 反复开卡 8 次 | 5.9MB | **−46%** |

**总体：同一串操作后画布占用 11.0MB → 5.9MB（约 −46%）。**

另在模拟 retina（设备倍率 2）下单独验证：舞台画布从 DPR 2.0（约 18MB）降到 **1.47（9.9MB）**，
小屏仍取满 2 倍；视觉上无肉眼差别（截图为证）。

## 边界与取舍

- 懒渲染的缩略图用同一物种、同一批种子重算，因此滚动到哪张画哪张，外观与原来一致（截图核对）。
- 释放策略只针对"重开即重建"的画布（角色库、预设、卡片），舞台与纸张纹理不动。
- 页面切到后台时顺带停掉乐曲与"移动出声"的最近记录，避免后台继续发声/记账。
- 未做：把舞台整体搬到 OffscreenCanvas 或换 WebGL（收益不确定、风险高，这一轮不动）。
