# r30：大合照的键位从 `~` 挪到 `;`

2026-09-23。**这条是修正 r29 的一个自造冲突**——你指出得对：反引号键（键帽上印着 `~`）是「说话」的快捷键。

## 冲突到底在哪

基线的键盘处理里，最前面就有一条：`` if(e.key==='`'){ openSay(); return; } ``，而帮助面板里也写着
`` ` — 说句话 ``。也就是说**这颗键属于「说话」**。我在 r29 给大合照挑了 `~`——它正是同一颗键的
Shift 形式（`~` = Shift + `` ` ``），于是：

- 不加 Shift 按它：仍然开「说话」（没坏）；
- 加 Shift 按它：变成大合照（基线里本来是"什么都不做"）；
- 更要命的是**帮助面板里两行挤在一起**：`` ` — 说句话 `` 旁边就是 `` ~ — 大合照 ``，
  同一个键帽标了两种含义。

当时的想法是"说话用不着 Shift 形式，空着也是空着"，但对使用者来说这颗键就写着 `~`，
占了它就是抢了「说话」的键。**这是我把"代码里没被占用"当成了"用户心里没被占用"。**

## 现在

- 大合照改用**分号键 `;`**（在 L 键右边，单手好按）；`:` 是同一颗键的 Shift 形式，两个都能用；
- 中文输入法下按同一颗键可能送来全角 `；`/`：`，也一并接受，四种写法等效；
- **`~` 交还出去**：现在按它什么都不做，与基线一致；
- 帮助面板里「说话」和「大合照」各占一行，不再打架。

## 验证

浏览器实测（CDP 真按键，非直接调函数）：

| 操作 | 结果 |
| --- | --- |
| 按 `` ` `` | 说话框打开，焦点落在输入框 ✓ |
| 在说话框里打 `;` | 不触发合照（输入框内的按键不劫持）✓ |
| 按 `~`（Shift+`` ` ``） | 无反应 —— 已交还 ✓ |
| 按 `;` | 大合照启动 ✓ |
| 按 `:`（Shift+`;`） | 大合照启动 ✓ |
| 帮助面板 | 末行出现「;  Group photo」并带完整说明；不再有 `~` 行 ✓ |
| 按 `n` 换脸后 Ctrl+Z | 正常回滚（基线里那个同名的 `snapshot()` 未被顶掉）✓ |

全程无 pageerror / console.error。
