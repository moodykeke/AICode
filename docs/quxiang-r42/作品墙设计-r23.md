# r23：作品墙——把"做出来"接上"被看见"

2026-09-23。P0-A 落地：趣像里的一张卡可以直接挂到校园作品墙，点开还能回到同一张脸。

## 一、闭环

```
趣像里双击角色 → 卡片 → 「送去展墙」
        ↓（出图 + 作品码 + 发布）
校园作品墙（/campus/wall）——匿名可浏览
        ↓（点开展品）
「在趣像里看这张脸」→ /static/fun/quxiang/#<作品码> → 原样打开同一个角色
```

**作品码是作品的一部分**：提交时把角色 DNA 写进项目的 `main.txt`（非 snap 类型的主文件约定），
展墙读回来就能"带着作品回到现场"，而不是只挂一张图。

## 二、通道（全部复用平台既有能力，未改后端）

| 环节 | 用的接口 |
| --- | --- |
| 投稿 | `POST /api/v1/projects/{用户名}/{作品名}`：`project_type=quxiang` + `thumbnail`(data URI) + `extra_files.main.txt`(作品码) + `notes`/`project_metadata` |
| 上墙 | 同项目 `POST .../metadata?ispublic=true&ispublished=true` |
| 展墙列表 | `GET /api/v1/projects/browse?project_type=quxiang&status=published`（匿名可读） |
| 我的作品 | `GET .../browse?...&status=shared&username=<自己>` |
| 作品码 | `GET /api/v1/projects/{用户名}/{作品名}` → `content` |
| 出图 | `GET /api/projects/{id}/thumbnail` |

## 三、踩到的三个坑（都已在代码里注明）

1. **非 snap 项目必须带主文件**：`primary_file(project_type)` 未知类型回落 `main.txt`，保存后会校验其存在，
   只发 thumbnail 会得到 500（且此时行已插入——属平台侧未回滚）。
2. **请求体 2MB 上限**：卡片 1020×1428 PNG 转 base64 约 2.8MB → 413。
   展墙用图改为 **2 倍尺寸 JPEG（0.88）**，并留一档降尺寸兜底；体积约两百分之一。
3. **可见性口径**：匿名与教师都只看得到 `ispublished=true`；`status=shared` 只有**教师**能列出全部，
   学生需要带 `username=<自己>` 才看得到自己的。而 `.../metadata` **只允许作者本人**（教师 403）。

## 四、因此的审核口径（重要）

平台既有的发布权**只归作者本人**，这与作品广场的现状一致。所以：
- 提交即自发布上墙（可被匿名看到）；
- 作者可在展墙上**就地撤下**（本人操作的权限是够的）；
- 教师**不能**替学生撤下或发布——这条留给了"撤下靠作者、教师提醒"的现状。
  若要做到"教师一键撤下"，需要后端加一条带角色判定的路由（我未擅自改后端，待你定）。

## 五、页面（高艺术部分）

- 题壁式页头（宣纸底 + 纸纹 + 题词"四十二张脸，有人把它们留了下来"），与拾趣馆同一套博物馆语言。
- 展品＝白卡纸 + 木框 + 展签（题名/作者），悬停轻抬并微微倾斜，像挂在墙上的纸片。
- 详情灯箱：大图 + 展签 + 作品码 + 「在趣像里看这张脸」/「挂上展墙 / 从展墙撤下」。
- 门户第三扇门「作品墙」（与影院、拾趣馆并列），门卡显示已上墙件数。

## 六、验证（浏览器实测）

- 未登录：展墙可浏览、给出登录提示；在趣像点「送去展墙」只提示，不影响本地导出与全部玩法。
- 学生：投稿成功 → **匿名立刻可见**（1 件）→ 本人的「我的作品」里可就地撤下（撤下后展墙不再显示）。
- 灯箱：题名、作者、**作品码**、按钮齐全；深链 `/static/fun/quxiang/#<码>` **能原样打开那张脸**。
- 门户：三扇门与作品墙件数正确；无控制台错误。
