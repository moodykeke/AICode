# r37：喜怒哀乐情绪件 —— 存储路径设计 + 生成管线 + 应用接入

前提：用户确认"卡通头像生成不涉及隐私"，模型版获批；本轮把**存储路径**设计好并打通全链。

## 一、存储路径设计（唯一写入者：`bin/generate-avatar-emotions.py`）

```
直出根（内网 /home/snapcloud/avatars/ ←nginx→ 外网 /opt/snapcloud/avatars/，同结构）
avatars/
├── avatar_<uid>.png              原始件：平台上传/早期生成。**只读，绝不写**
└── unified/                      派生件：全部可重跑，不入 git
    ├── index.json                基线清单（来源、时间、处理参数）
    ├── base|paper|ink|wash|round|display/<uid>.png
    └── emotion/
        ├── index.json            **情绪件清单 + 溯源**（来源文件/渲染器/模型/提示词哈希/时间/字节/sha）
        ├── _sheet_<emotion>.jpg  每情绪一张抽检拼图（人工复核）
        └── <emotion>/<uid>.png   emotion ∈ joy|anger|sorrow|delight
```

设计要点：
- **一学生一情绪一个稳定路径**，重跑即覆盖（幂等）；前端缓存用 `index.json.version` 拼 `?v=` 打倒；
- **原始件永不被覆盖**，派生件全在 `unified/` 下，删了随时重跑；
- **溯源**写进 `emotion/index.json`：谁从哪张来、用什么渲染器/模型、提示词哈希 —— 校园场景要能回溯"这张图怎么来的"；
- 双网：写完 `rsync unified/ → 外网同路径` 即直出；外网缺件时应用自动退回基线（`display/`）。

## 二、两个渲染器（同一份存储，可换）

| 渲染器 | 需要 | 说明 |
| --- | --- | --- |
| `cogview` | `ZHIPU_API_KEY` | 走仓库既有的智谱图像生成通道（`scripts/generate_role_portraits.py` 同源），把基线头像作参考图按情绪提示词**重绘五官表情**，质量高、有调用成本 |
| `marks` | 无 | 本地叠漫画情绪符号（腮红/星星、怒筋/竖眉、泪珠、笑纹彩点），确定性、零成本、可离线；**不改变五官**，用于先跑通存储与展示 |

**当前状态：环境里没有 `ZHIPU_API_KEY`**（`env` 与配置文件里都没有），所以模型版**代码就绪但未跑**；
如需要，把 key 放进运行环境即可：`python3 bin/generate-avatar-emotions.py --renderer cogview`。

## 三、应用接入（趣像班级人像）

设置 →「表情」：原始 / **喜 / 怒 / 哀 / 乐**。选中后班级墙与班级大合影即使用对应情绪件
（缺件自动退展示版→原始头像）。实测：切「喜」后自动重载，52/52 全部换成情绪件，大合影正常出片。
