# r33：教师可加载任一班级 + 深入检测修复三处 + 亲吻改「啵一下」+ 内存核算

## 一、教师可加载任一班级

- 数据源：**`/api/v2/edu/display/classes`（公开面，无鉴权，返回全校班级 id/名称/年级）** —— 教室屏的 WPF 就靠它。
- 选班面板现在分两段：**自己的班**（学生走 `/api/v2/student/classroom/classes`，教师走 `/api/v2/teacher/classroom/recent`）
  ＋ **全校班级**（仅教师可见，带搜索框；8 个班以上尤其有用）。
- 角色判定改用 **`/api/v2/auth/me`**（不再拿教师接口去试探）——学生侧因此不再产生一条 403 噪音请求，
  也**不会看到"全校班级"**（学生只能选自己名下的班）。
- 教师没带班时不再直接退出面板（原来 `list` 为空就 return，教师的"全校班级"整段都看不到）。

## 二、深入检测：发现并修掉三处（都是"看起来能用、其实在丢数据"）

1. **收尾被并发重复执行**：加载用 6 路并发，每一路收尾时都会走到完成分支；第二遍进来时 `CLASS.cards`
   已经是**新的一批**，于是刚建好的 52 张卡被当成"上一批"清掉 51 张（画布全变 1×1，画面空白）。
   → 加 `finished` 闸，收尾只做一次。
2. **按"派发完"收尾**：`next >= roster.length` 只代表派发完了，**还有请求在飞** → 后到的 5 张被丢（47/52）。
   → 改成按**完成数**收尾（`left` 递减到 0）。
3. **异常吞掉进度**：`createImageBitmap` 失败时链尾没有 catch → `left` 不递减 → 派发继续越过名单末尾 →
   `roster[i]` 为 undefined 抛 `reading 'id'`（每轮 2–3 次 pageerror）。
   → 链尾补 catch（失败记入 `failed` 清单）+ 派发前再守一道 `next >= roster.length`。

## 三、亲吻 → 啵一下

设置面板「K 键动作」的两个选项现在是 **碰头 / 啵一下**（英文侧仍是 Knock heads / Kiss）。

## 四、内存核算

- 卡片是**离屏画布**，`window.__mem`（只数挂 DOM 的）看不到它——已单独记账：`window.__class.bytes`。
- 实测：52 张卡 = **11.1MB**（每张 200×280×4 ≈ 224KB，正好对应舞台 ~100px 卡在 retina 下所需，不浪费）；
  载入前舞台 4.9MB → 载入后 4.9MB（卡走离屏，不占舞台画布）；**退出归零**；连续切班不再积压。
- 加载峰值会短暂多出 52 张基线的 ImageBitmap（各 256²，约 13MB），解码后立即 `close()` 释放。
