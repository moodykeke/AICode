# r43：性能与内存——画得更细，反而更快

2026-09-24。本轮重绘让角色更复杂；为了低配机器仍然流畅，同时做了三件事：半身像位图缓存、细节分级、弱机降分辨率。

## 一、先量：时间花在哪

- CPU 采样（无 GPU 的 headless Chromium，经典半身像舞台）：**81.7% 是原生光栅化**，JS 本身很少。
  也就是说，成本 ≈ 填充的像素 × 层数；水彩笔触每一笔都是"纸色遮挡 + 两层正片叠底 + 双遍墨线"。
- 单个角色绘制（120px 格，取 6 轮最小值）：r42 各系列平均 0.35–0.55ms/头；重绘后细节多的角色 0.8–1.0ms/头。
- 结论：只省细线没用（细节分级只省约 10%）；要省就得**少画整笔**。

## 二、半身像位图缓存（`portrait-sprite.js`）

各系列半身像是平面画法（转头只做水平压缩），可以缓存：每个角色在当前尺寸、画风、纸色下只画一次到离屏小画布，
舞台每帧贴图，**再按实时视线与眨眼重画登记过的眼睛**——目光跟随、眨眼、轻触回应都还在。

- 眼睛登记：`artEye*`、`folkPortraitEyes`、`naturalEyes`、`atlasEye` 在烘焙时只登记（函数、参数、相对变换），逐帧用实时 `o` 回放。
- 照常逐笔现画：伸脖、融化/冰冻、半透明、招牌动作与风中摆动（`perform`/`wind`）、大合影全程、卡片/导出/打印分辨率（每单位 >110 设备像素）、
  伞怪（独眼即脸）、烛龙（闭眼焰暗）。
- 缓存键：物种 · 衣色 · 借体 · 标志档 · 画风 · 彩色/单色 · 尺寸；纸色、调色板版本、线宽、抖动变了整体清空。
- 网格构图按实际尺寸烘焙（1:1 贴图不发虚）；簇状/单人构图大小不一，按 6% 一档合用。
- 内存：LRU 上限 3MB，页面隐藏即清空。实测一个系列 8–9 条、0.5MB；做一次大合影后仍是 9 条、0.5MB。
- 经典半身像（上游 Head Cases 的 3D 头）会随指针三维转动，不缓存。

## 三、细节分级（`ART_DETAIL_PX`）

7×5 舞台上每单位只有约 40–60 设备像素，1–2px 的装饰看不见却很费时。每单位不足 64 设备像素时跳过它们，
卡片、导出与打印合影仍画全。弱机兜底：舞台最近帧绘制持续 >30ms 时整体改简版，降回 <18ms 才恢复（带回差，不会来回闪）。

## 四、弱机降分辨率（`ux-r43.js`）

舞台连续 3 秒每帧绘制 >34ms 时，逐级降低舞台分辨率（每级 ×0.8，最低 1 倍）；`layout()` 之后仍保持（`QX_DPR_SCALE`）。
只对高分屏有效（手机、平板、retina），1 倍屏不动；拍照提分辨率期间不动。

实测（390×844、DPR 2、CPU 6 倍降速）：1.75 → 1.4 → 1.12，舞台像素 93.6 万 → 38.3 万（−59%）。1366×768 DPR 1：不变。

## 五、手机默认 4×6

竖屏手机（窄边 <520px）默认 4×6（24 位）而不是 7×5（35 位）：每张脸约大一倍（点得准），每帧少画 31% 的角色。
只影响从没选过网格的访客（`quxiang.gridChoice` 未设）；点"舞台"摘要按钮回到本机默认。

## 六、结果（4 倍 CPU 降速，1280×800，DPR 1；headless 无 GPU，数值偏悲观，看相对变化）

| 场景 | r42 每帧绘制（中位数） | r43 | 变化 |
| --- | --- | --- | --- |
| 欧洲与希腊神话 | 109.6ms | 38.3ms | −65% |
| 西游行旅 | 97.6ms | 33.0ms | −66% |
| 经典半身像 | 90.3ms | ≈ 同（3D 头不缓存，波动范围内） | — |

| 内存 | r42 | r43 |
| --- | --- | --- |
| 载入后 JS 堆 | 4.5MB | 4.6MB |
| 载入后画布 | 4 张 6.6MB | 4 张 6.6MB |

| 产物体积 | 720KB | 802KB（+11%，解析时间可忽略） |

## 七、怎么复测

- 调试出口：`window.__sprite.stats`（条数 / MB / 烘焙次数 / 命中 / 现画次数），`__sprite.on = false` 可关掉缓存对比；
  `window.__lowpower`（当前降级系数与 DPR）；原有 `window.__mem`。
- 画布归属：缓存画布打 `portrait-sprite` 标签，`Runtime.queryObjects(HTMLCanvasElement.prototype)` 可点名统计。
- 对比方法：同一 7×5 场景、同样的指针轨迹，包一层 `drawGrid` 记每帧耗时，CDP `Emulation.setCPUThrottlingRate` 4 倍。

## 八、还没做（见《界面与键位-高观点改造方案-r43.md》第五节）

经典半身像（默认首屏）的逐帧成本仍是最高的；可选方向：按转角分档缓存、静止帧跳画（没有任何变化就不重画）、设置里显式的"省电模式"。
